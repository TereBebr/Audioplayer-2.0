# Передача контекста: где проект и что осталось

Файл для входа в проект с нуля — например, в новом чате. Читать первым, дальше
по ссылкам.

Проект: музыкальный плеер на Python + Flet + VLC, который умеет играть и с локального
диска, и с домашнего сервера на Raspberry Pi 4 с HDD.

## 2. Архитектура в двух абзацах

**Клиент не знает, откуда трек.** Везде, где раньше были `Path`, `mutagen.File`,
`iterdir`, теперь стоит `sources.get(uri)` — он возвращает `LocalSource` или
`RemoteSource`, у которых **одинаковые имена методов**. `load_track`, `add_queue`,
проводник, плейлисты написаны один раз и работают с обоими. Решение «локальный или
серверный» принимается ровно в одном месте — `sources.get()`.

**Трек адресуется строкой.** Локальный — обычный путь (`C:\music\a.flac`), серверный —
`srv://home/t/48213`, папка на сервере — `srv://home/d/Rock/Muse`. Эта строка лежит в
колонке `path` в `queue.db` и `app.db`. Схемы БД не менялись, старые базы читаются
без миграции. `48213` — это `id` строки в `library.db` **на сервере**; клиент в эту
базу не ходит никогда, он делает HTTP-запрос, а SQL выполняет сервер.

```
         load_track / add_queue / проводник / плейлисты
                            |
                    sources.get(uri)
                     /            \
            LocalSource          RemoteSource
         mutagen + Path        HTTP -> Raspberry Pi
                                        |
                                   server.py -> library.db
```

## 4. Эндпоинты сервера

Префикс `/server/`. Корень библиотеки — `folder_path=""`.

| Метод | Путь | Отдаёт |
|---|---|---|
| GET | `/server/ping` | статус, версия, число треков, `library_uuid`, прогресс скана |
| GET | `/server/browse?folder_path=` | папки с диска + треки из индекса |
| GET | `/server/search?q=&folder_path=` | поиск по тегам и пути, без учёта регистра; `folder_path` — только в папке |
| GET | `/server/tracks_under?folder_path=` | треки папки и всех подпапок |
| GET | `/server/track/{id}` | полная строка трека |
| GET | `/server/tracks?ids=1,2,3` | то же пачкой, до 500 |
| GET | `/server/track/{id}/cover?size=50\|full` | JPEG |
| GET | `/server/stream/{id}` | аудио как есть, **с HTTP Range** |
| POST | `/server/rescan?full=` | фоновая переиндексация |

Запуск: `cd server && python -m uvicorn server:app --port 8000`
Индексация: `cd server && python indexer.py` (`--full`, `--purge`, `--stats`)

## 5. Что осталось

### Э6. Поиск по индексу сервера — ✅

Сделано по `TZ_stage6_search.md`. В серверном режиме поиск идёт по индексу всей библиотеки
или текущей папки с подпапками (кнопка справа от строки поиска), с debounce 300 мс и
отбрасыванием устаревших ответов. Локальный режим — фильтр по открытой папке, как раньше.

### Э7. Устойчивость — ✅

Сделано по `TZ_stage7_resilience.md`: длительность для слайдера из меты сервера, новый
`bg_ui_process` (буферизация, повторы с продолжением с места обрыва, пропуск, пауза после
серии неудач), `RemoteSource._get` не ходит в сеть при `enabled = False` и когда опрос знает,
что сервера нет. `.exe` собирается (`build.ps1`) и запускается.

**7.6 Токены — ✅.** `server.ini` → `[Tokens]`: «имя = токен», по строке на человека;
старый одиночный `[Server] token` тоже работает (имя `owner`). Ни одного токена — сервер
открыт. Свой токен человек вписывает в `config.txt` плеера, `[Server] token`. Отозвать —
удалить строку и `systemctl restart musicserver`. Middleware `check_token` (`server.py`)
требует `Authorization: Bearer <token>` на всех путях, включая `/docs`; стрим VLC заголовок
не шлёт, поэтому `RemoteSource.mrl` добавляет `?s=<stream_sig>` — HMAC от токена и id трека
(`stream_sig` — две копии, `server.py` и `sources.py`). В `journalctl -u musicserver`:
«sasha слушает трек 42». Неверный токен в логе плеера — «401: токен в config.txt не
совпадает с server.ini».

Сервер живёт на Pi (Armbian) в `/root/musicserver`, systemd-юнит `musicserver`, музыка —
`/mnt/hdd/music` (NTFS, `ntfs3`). Снаружи — через Tailscale, имя `musicpi`.

### Э8. Офлайн-кэш (опционально)

«Скачать на устройство»: трек кладётся в локальный кэш, URI остаётся `srv://`, но
`mrl()` отдаёт локальный файл.

## 6. Грабли, на которые уже наступали

Это не теория — каждый пункт стоил отладки.

**Контролы Flet нельзя менять из фонового потока.** Изменения до клиента не доходят:
данные загрузились, а на экране старое, пока не кликнешь что-нибудь. Правило:
из потока — только `page.pubsub.send_all_on_topic(...)`, а UI меняет уже обработчик
pubsub. Так сделано в `bg_ui_process`, `on_dir_ready`, `on_queue_progress`,
`on_cover_ready`, `on_server_status`.

**Поток умирает молча.** Дважды: `return` вместо `continue` в `cover_worker` и
обращение к неинициализированной переменной в `queue_worker`. Оба раза исключение
летело вне `try`, поток завершался, и фича просто переставала работать без единой
записи в логе. Проверять: тело потока целиком должно быть под `try`.

**`request_cover` ничего не возвращает.** Это «попроси и забудь»: кладёт URI в очередь,
результат приходит позже в БД и через pubsub. Трижды использовалась как
`miniature = request_cover(...)`.

**`Path(uri)` на серверном URI.** На Windows `Path("srv://home/t/1").resolve()` молча
даёт `C:\...\srv:\home\t\1`. Ни ошибки, ни трека. Выше слоя источников `Path()` быть
не должно: `grep -n "Path(\|mutagen.File\|iterdir\|rglob" ui_utils.py gui2.py` должен
находить только `sources.py`.

**`is_remote` — атрибут у классов, функция у модуля.** `src.is_remote` без скобок,
`sources.is_remote(uri)` со скобками. Перепутать легко, `TypeError: 'bool' object is
not callable`.

**Копировать SQLite в WAL-режиме через `cp` нельзя.** База — это три файла
(`.db`, `-wal`, `-shm`); копирование одного главного ломает её
(«database disk image is malformed»). Один раз уже убило `queue.db`, восстанавливали
переносом строк. Только `src.backup(dst)` через API.

**Битрейт сервер отдаёт уже в кбит/с** — в `RemoteSource.details` делить на 1000 не надо,
в отличие от `LocalSource`.

**Заглушки меты не писать в БД.** Если сервер недоступен, `meta` возвращает словарь с
`_stub: True`; такие треки `queue_worker` и `add_track_to_playlist` пропускают. Иначе
имя «Трек 1 (сервер недоступен)» осядет в `app.db` навсегда.

**Перемотка держится на HTTP Range.** `/server/stream/{id}` обязан отвечать `206` —
`FileResponse` умеет, ручной `StreamingResponse` нет. Проверка:
`curl -r 0-1023 -o /dev/null -D - http://127.0.0.1:8000/server/stream/1`

## 7. Главное требование, которое легко забыть

> Плеер без сервера, с сервером и с выключенным сервером должен вести себя одинаково
> хорошо. Ни одна из существующих функций не деградирует.

Это не «локальная версия» и «серверная версия», а один плеер с двумя источниками
одновременно. Очередь и плейлисты могут быть смешанными, автопереход
«локальный → серверный → локальный» обязан работать, а при выключенном Pi серверные
треки остаются в списках и помечаются серым, а не удаляются.

Регрессионный чеклист локального режима — 24 пункта в `TZ_streaming.md`, раздел 7.3.
Прогонять после каждого этапа, который трогает общий код.
