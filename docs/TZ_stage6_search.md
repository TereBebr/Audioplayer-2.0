## 6.2 Сервер

### 6.2.1 Что должен уметь поиск

Было: подстрока ищется в `name`, `author`, `album`, регистр учитывается для кириллицы.

Надо:

1. **Искать ещё и в `rel_path`.** Там имя файла и все папки над ним
   (`Rock/Muse/Absolution/04 Hysteria.flac`). Тогда находятся треки без тегов (у них
   `author` пустой, `name` = имя файла) и все треки папки по её названию.
2. **Не учитывать регистр для любого языка** (см. 6.2.2).
3. **По желанию ограничиваться папкой** (см. 6.2.3), для переключателя «В папке».

Папки отдельными строками в ответе не возвращаются, только треки.

### 6.2.2 Регистр

**Проблема.** `LIKE` в SQLite не учитывает регистр только для латиницы:
`'Muse' LIKE '%muse%'` — да, `'Кино' LIKE '%кино%'` — **нет**. Ошибки при этом нет,
просто пустой результат.

**Решение.** В Python `"Кино".casefold()` → `"кино"` работает для любого языка. SQLite
позволяет подключить Python-функцию к соединению и вызывать её прямо из SQL:

```python
# db.py, внутри get_conn(), перед return
def _fold(s):
    if s is None:
        return None
    return s.casefold().replace("ё", "е")

con.create_function("py_fold", 1, _fold, deterministic=True)
```

После этого в SQL можно писать `py_fold(author)`: SQLite вызовет `_fold` для каждой
строки. Обе стороны сравнения приводятся к одному виду:

* поля в SQL — через `py_fold(...)`;
* запрос пользователя — в Python, тем же `casefold().replace("ё", "е")`, до того как он
  попадёт в шаблон `%...%`.

`ё → е` — потому что в тегах встречаются оба варианта.

### 6.2.3 Ограничение папкой — ✅ СДЕЛАНО

**Зачем.** Переключатель «В папке»: стоим в `Rock/Muse`, ищем `live` и получаем только
треки из `Rock/Muse` и её подпапок.

**Условие уже есть** в `tracks_under_dir` (`db.py`):

```sql
dir = ? OR substr(dir, 1, ?) = ?
--     параметры: rel_dir, len(prefix), prefix,  где prefix = rel_dir + "/"
```

`substr(dir, 1, N)` — первые N символов `dir`. Для `rel_dir = "Rock/Muse"`:

| `dir` трека | подходит | почему |
|---|---|---|
| `Rock/Muse` | да | `dir = rel_dir` — сама папка |
| `Rock/Muse/Absolution` | да | начинается с `Rock/Muse/` — подпапка |
| `Rock/Museum` | нет | `/` в конце префикса отсекает похожие имена |
| `Pop` | нет | |

**Что сделать.** `search_tracks` получает аргумент `rel_dir: str = ""` (в эндпоинте он же `folder_path`). Пустой — условия
нет, ищем по всей библиотеке. Непустой — условие добавляется к `WHERE` через `AND`.
Строку SQL и список параметров собираем в Python по кускам:

```python
where = "missing = 0 AND <условие поиска из 6.2.4>"
params = [pat]
if rel_dir:
    prefix = rel_dir + "/"
    where += " AND (dir = ? OR substr(dir, 1, ?) = ?)"
    params += [rel_dir, len(prefix), prefix]
params.append(limit)
con.execute(f"SELECT * FROM tracks WHERE {where} ORDER BY ... LIMIT ?", params)
```

Подставлять в f-строку можно только **собственные куски SQL**. Пользовательские
значения — только через `?` и `params`.

### 6.2.4 `search_tracks` целиком — ✅ СДЕЛАНО

Сигнатура: `search_tracks(con, query, limit=200, rel_dir="")`. Папка в `server.py` называется
`folder_path` (так она приходит в URL), в `db.py` — `rel_dir` (как в `tracks_under_dir`). Это одно и то же.

Шаги:

1. `q = query.strip()`; пустой → `return []` (уже так).
2. `q = q.casefold().replace("ё", "е")`.
3. Экранирование `\ % _` — как было: `q.replace("\\", "\\\\").replace("%", "\%").replace("_", "\_")`.
   Порядок 2 и 3 не важен.
4. `pat = f"%{esc}%"`.
5. Условие поиска — одно на все четыре поля:
   ```sql
   py_fold(coalesce(name,'') || ' ' || coalesce(author,'') || ' ' ||
           coalesce(album,'') || ' ' || rel_path) LIKE ? ESCAPE '\'
   ```
   * `||` — склейка строк в SQL.
   * `coalesce(x, '')` — пустой тег в базе хранится как `NULL`, а `NULL || 'abc'` даёт
     `NULL` и ломает всю склейку.
   * Склейка вместо четырёх `OR` — чтобы `py_fold` вызывался 1 раз на строку, а не 4.
     Если четыре `OR` понятнее, можно и так, но тогда в `params` четыре `pat`.
   * Один `?`, значит, и в `params` один `pat`.
6. Условие папки из 6.2.3.
7. `ORDER BY author COLLATE NOCASE, album COLLATE NOCASE, rel_path LIMIT ?`.

**Ловушка с обратным слешем.** В SQL нужно получить `ESCAPE '\'` — один слеш. В обычной
Python-строке, в том числе `'''...'''`, `\'` превращается в `'`. Поэтому в Python-коде
пишется `ESCAPE '\'`, как и было в исходной версии. Либо raw-строка `r"..."`.

### 6.2.5 Эндпоинт — ✅ СДЕЛАНО

Было:

```python
@app.get("/server/search")
def all_library_search(filename: str):
    with closing(db.get_conn(cfg.db_path)) as con:
        content = db.search_tracks(con, filename, search_tracks_limit)
    return content
```

Надо:

```python
@app.get("/server/search")
def all_library_search(q: str, folder_path: str = ""):
    if folder_path:
        folder = safe_path(folder_path)          # 403, если путь ведёт наружу
        if not folder.is_dir():
            raise HTTPException(404, "folder not found")
    with closing(db.get_conn(cfg.db_path)) as con:
        content = db.search_tracks(con, q, folder_path, search_tracks_limit)
    return content
```

Как FastAPI работает с параметрами: в декораторе **только путь**. Всё, что после `?` в
URL, FastAPI раскладывает по аргументам функции по имени:
`/server/search?q=muse&folder_path=Rock` → `q="muse"`, `folder_path="Rock"`. Аргумент без
значения по умолчанию (`q`) обязателен, без него будет `422`. Аргумент с `= ""` —
необязательный.

`filename` → `q`: ищем теперь не только по имени файла. Клиент этот параметр ещё не
использует, ломать нечего. В `HANDOFF.md` поправить таблицу эндпоинтов.

### 6.2.6 Проверка сервера

Перезапустить uvicorn, затем:

```bash
curl "http://127.0.0.1:8000/server/search?q=muse"
curl "http://127.0.0.1:8000/server/search?q=MUSE"                       # то же самое
curl "http://127.0.0.1:8000/server/search?q=%D0%BA%D0%B8%D0%BD%D0%BE"   # «кино» находит «Кино»
curl "http://127.0.0.1:8000/server/search?q=flac"                        # по rel_path
curl "http://127.0.0.1:8000/server/search?q=a&folder_path=Rock/Muse"     # только внутри папки
curl "http://127.0.0.1:8000/server/search?q=%25"                         # «%» буквально, не «всё»
curl "http://127.0.0.1:8000/server/search?q=x&folder_path=../.."         # 403
curl "http://127.0.0.1:8000/server/search?q="                            # []
```

Удобнее через `http://127.0.0.1:8000/docs`: FastAPI сам рисует форму с полями `q` и
`folder_path`.

**Производительность.** `LIKE '%...%'` не использует индексы: SQLite проходит все строки
и на каждой вызывает Python. На Pi с десятками тысяч треков это ориентировочно
0,1–0,2 с. Если выйдет заметно медленнее, смотри 6.7.

## 6.3 Слой источников — ✅ СДЕЛАНО

### 6.3.1 Сигнатура

Одинаковая у обоих классов, как и всё остальное в `sources.py`:

```python
def search(self, query: str, folder_uri: str | None = None, items: list | None = None) -> list | None
```

| Аргумент | `LocalSource` | `RemoteSource` |
|---|---|---|
| `query` | подстрока | подстрока |
| `folder_uri` | не используется | `None` — вся библиотека, URI папки — только в ней |
| `items` | что фильтровать (`explorer_tree.all_items`) | не используется |

Возвращает список в формате `list_dir`: `[{"name", "path", "type"}]`.

### 6.3.2 `LocalSource.search`

Текущий фильтр из `perform_search`, перенесённый как есть. Сети нет, синхронный.
Регистр: `casefold()` вместо `lower()` и такая же замена `ё → е`, чтобы локальный и
серверный поиск вели себя одинаково. Функцию `_fold` можно положить в `sources.py`
(на сервере своя копия, у них общего кода нет).

### 6.3.3 `RemoteSource.search`

Схема шагов (не код, код — по образцу `list_dir` и `expand` в том же классе):

```
_parse(folder_uri) -> rel            (если folder_uri задан)
_get("/server/search", params={"q": query, "folder_path": rel})
_prime(rows)                         <- обязательно
-> [{"name": ..., "path": self._track_uri(row["id"]), "type": "track"} for row in rows]
```

* **`_prime(rows)`** кладёт строки в кэш меты. Без него двойной клик по найденному
  треку или «Добавить в очередь» на 200 результатах снова пойдут на сервер за каждой
  строкой. Это та же ловушка, что закрывали в Э5.
* **Что показывать в `name`.** В `list_dir` для трека это название из тегов, и внутри
  одной папки этого хватает. В поиске по всей библиотеке будет пять строк «Intro» и
  непонятно, чьи они. Поэтому для результатов поиска: `f"{author} — {name}"`, если
  `author` не пустой, иначе просто `name`.
* **Пустой результат и недоступный сервер — разные вещи.** По соглашению `RemoteSource`
  не выпускает исключения наружу (комментарий у `list_dir`). Но UI должен показать
  разный текст. Поэтому:
  * `RemoteUnavailable` → залогировать, вернуть **`None`**;
  * `RemoteNotFound` (папку удалили) → залогировать, вернуть `[]`;
  * нашлось ноль треков → `[]`.

### 6.3.4 Проверка из REPL

```python

r.search("muse")[:3]
r.search("muse", "srv://home/d/Rock")
r.search("zzzzzz")        # []
# остановить uvicorn
```

## 6.4 Интерфейс — ✅ СДЕЛАНО

### 6.4.1 Переключатель области поиска

Кнопка-иконка справа от `search_bar`, в половину его высоты (`search_scope_btn`, 16×10):

| Состояние | Иконка | Подсказка (`tooltip`) | Что ищем |
|---|---|---|---|
| «В папке» | `ft.Icons.FOLDER_OUTLINED` | «Искать в текущей папке» | текущая серверная папка **с подпапками** |
| «Везде» | `ft.Icons.PUBLIC` | «Искать по всей библиотеке» | весь сервер |

* По умолчанию **«Везде»**, ради этого этап и делается.
* Видна **только в серверном режиме** (`explorer_view.data["mode"] == 1`). В локальном
  режиме «везде» не определено, там поиск по текущей папке, как сейчас.
* Состояние хранить в `explorer_view.data["search_scope"]` (`"all"` / `"folder"`),
  рядом с `mode`. Между запусками не сохраняется: не нужно.
* Клик по переключателю при непустом запросе сразу перезапускает поиск, без debounce.

> Разница с локальным режимом: локально «текущая папка» — без подпапок, на сервере —
> с подпапками. Это осознанно: локально рекурсивный обход диска медленный, а на сервере
> это один SQL-запрос.

### 6.4.2 Поток данных

```
on_change (UI)
   |
   +-- локальный режим ---> LocalSource.search(q, items=all_items) ---> rebuild_explorer
   |                         (синхронно, как сейчас)
   |
   +-- серверный режим
          |  seq += 1; отменить старый таймер
          |  q пустой ---------------------------------------------> rebuild_explorer(all_items)
          |  len(q) < 2 --------------------------------------------> ничего не делать
          v
       threading.Timer(0.3)
          v  (поток таймера)
       run_bg(REMOTE.search, q, folder)
          v  (фоновый поток)
       pubsub "search_ready" {seq, items | None}
          v  (Flet)
       on_search_ready: seq устарел? -> выбросить
                        items is None -> «Сервер недоступен»
                        [] -> «Ничего не найдено»
                        иначе -> rebuild_explorer(items, current_dir, is_search=True)
```

### 6.4.3 Debounce

Отдельные переменные, **не** `_loading_timer` проводника, иначе поиск будет гасить
индикатор загрузки папки и наоборот:

```python
_search_timer = [None]
_search_seq   = [0]
SEARCH_DELAY  = 0.3
MIN_QUERY_LEN = 2
```

Приём тот же, что в `open_dir` (`gui2.py:1785`): при каждом нажатии старый таймер
`cancel()`, новый `start()`, `daemon = True`.

`MIN_QUERY_LEN = 2` — только для сервера. Один символ даёт совпадение почти с каждой
строкой и упирается в лимит 200, в сеть такой запрос гонять незачем.

### 6.4.4 Устаревшие ответы

Сценарий: пользователь вводит `mu`, запрос ушёл; дописывает `muse`, ушёл второй запрос.
Первый по какой-то причине отвечает позже второго и **затирает правильный результат**.

Защита: номер запроса. `_search_seq[0] += 1` при **каждом** изменении поля (и при
очистке, и при смене папки, и при переключении режима). Номер уходит вместе с запросом и
возвращается в pubsub. В `on_search_ready`, если `message["seq"] != _search_seq[0]`, ответ
выбрасывается.

Тот же приём, что `_pending_dir` в `on_dir_ready`, только номер вместо URI: запрос
`muse` можно отправить дважды, и URI тут не помогает.

### 6.4.5 `rebuild_explorer`

Две правки:

1. Параметр `empty_text: str | None = None`. Если задан, рисовать его вместо «Ничего не
   найдено» / «Папка пуста». Нужен для «Сервер недоступен».
2. Сейчас при `is_search=False` он чистит `search_input`. Это правильно: переход в
   папку сбрасывает поиск. Но заодно надо делать `_search_seq[0] += 1` и отменять таймер,
   иначе запоздавший ответ поиска нарисуется поверх только что открытой папки.

### 6.4.6 Где ещё сбросить поиск

* Переключение «Локально / Сервер»: обработчик сегмента. Обычно это уже происходит
  через `open_dir` → `rebuild_explorer(is_search=False)`, но проверить.
* `on_server_status`, когда сервер пропал во время поиска: тоже уходит в `open_dir`,
  проверить, что поле очищается и висящий ответ выбрасывается.

### 6.4.7 Что не меняется

Результаты рисует тот же `rebuild_explorer`, поэтому drag&drop в очередь, контекстное
меню, двойной клик и «Добавить в плейлист» работают как в обычной папке, ничего
дописывать не нужно. Кнопка `...` наверху ведёт к родителю **текущей папки**, а не
найденного трека. Это нормально.

Индикатор `explorer_loading` для поиска не показываем: debounce плюс 100–200 мс ответа,
он только мигал бы. Если на внешней сети будет заметная задержка, можно включить тем же
приёмом с отложенным таймером. Это не входит в этот этап.

### 6.4.8 Доработки после первой проверки — ✅ СДЕЛАНО

* **Порядок результатов** — `search_rank.py` (копия в `server/search_rank.py`, менять обе).
  `rank(query, title, author)` → 0..7: исполнитель = запрос; запрос — целое слово в
  исполнителе; целое слово в названии; исполнитель начинается с запроса; подстрока в
  исполнителе; название начинается с запроса; подстрока в названии; остальное (альбом,
  путь). На сервере подключена в SQL как `py_rank` и стоит первой в `ORDER BY` — поэтому
  `LIMIT 200` отрезает наименее подходящие. Локально `LocalSource.search` сортирует тем же
  `rank` по имени файла/папки.
* **Хоткеи в текстовых полях.** Пока фокус в `ft.TextField`, `on_keyboard` ничего не
  делает. Поля регистрируются через `typing_field(...)` в начале `App` — сейчас это поиск и
  четыре поля диалогов плейлиста. Новое текстовое поле — тоже оборачивать.
* **Кнопка области — и в локальном режиме.** Область своя у каждого режима
  (`_search_scope` в `gui2.py`):

  | Режим | Папка (иконка `FOLDER_OUTLINED`) | Глобус (`PUBLIC`) |
  |---|---|---|
  | Локальный | фильтр открытой папки, сразу — **по умолчанию**, как было до Э6 | вся локальная библиотека (`start_path`) с подпапками, в фоне после паузы |
  | Сервер | текущая папка с подпапками | вся библиотека Pi — **по умолчанию** |

  Локальный поиск по библиотеке — `LocalSource.search(query, folder_uri)` без `items`:
  `os.walk` по `folder_uri`, совпадение в пути от корня (имя файла и папки), только треки,
  порядок по `search_rank`, не больше 200. Список файлов кэшируется на 60 с
  (`LocalSource.WALK_TTL`), иначе диск обходился бы на каждую паузу в наборе.
* **Кнопка области:** настройки в `ui_config.txt`, секция `[UI search_bar]`, ключи
  `search_scope*` (размер, подъём `search_scopeLift`, иконка, фон, рамка, скругление). Все с
  `fallback`, старый конфиг без них работает. Смена иконки: у `ft.Icon` свойство `icon`,
  а не `name`.

## 6.5 Крайние случаи

| Ситуация | Ожидаемое поведение |
|---|---|
| Пустой запрос | содержимое текущей папки, без сети |
| 1 символ, серверный режим | ничего не происходит, показана текущая папка |
| `%`, `_`, `\` в запросе | ищутся буквально |
| Кириллица в другом регистре, `ё`/`е` | находит |
| Ноль совпадений | «Ничего не найдено» |
| Сервер упал между вводом и ответом | «Сервер недоступен», приложение работает дальше |
| Быстрый ввод `m-u-s-e` | один запрос (debounce), на экране результат `muse` |
| Ввёл запрос и сразу кликнул папку | открылась папка, поздний ответ поиска выброшен |
| Ввёл запрос, переключился на «Локально» | локальная папка, поле пустое, ответ выброшен |
| 200 результатов (лимит) | показываем 200. Подпись «показаны первые 200» — по желанию, 6.7 |
| Двойной клик по найденному | играет, без лишнего запроса за метой (`_prime`) |
| «Добавить в очередь» на найденном | работает, как для трека из папки |

## 6.7 Не в этом этапе

* **Несколько слов** (`muse hysteria` — все слова в любых полях). Разбить запрос по
  пробелам, на каждое слово своё `AND ... LIKE ?`. Несложно, но сначала посмотреть,
  нужно ли.
* **Скорость на большой библиотеке.** Если `py_fold` на каждой строке окажется медленным:
  колонка `search_text` с уже приведённым текстом, которую заполняет индексатор (нужен
  `ALTER TABLE` и `--full`), либо FTS5. Не делать, пока не замерено.
* **Подпись «показаны первые N».** Сервер отдаёт `limit + 1` строк, клиент показывает
  `limit`, а лишнюю использует как флаг «есть ещё».
* **Индикатор загрузки для поиска.** См. 6.4.7.
* **Подсветка совпадения** в имени. Flet `TextSpan` это умеет, но к функциональности
  ничего не добавляет.
