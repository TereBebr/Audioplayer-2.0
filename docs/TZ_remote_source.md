# Э3. RemoteSource

## 3.0 Что это и чего здесь НЕ делается

`RemoteSource` — второй класс с **теми же именами методов**, что у `LocalSource`.
Ни один файл, кроме `sources.py` и `config.txt`, на этом этапе не меняется:
`load_track`, `add_queue`, `on_item_click` уже написаны так, что им всё равно.

**Не делается на Э3:** кнопка «Сервер» в интерфейсе (это Э4), обработка `Buffering`
в `bg_ui_process` (Э7), офлайн-кэш (Э8). Проверка этапа — ручная, через подмену
строки в `queue.db`.

## 3.1 Конфиг

Новая секция в `config.txt`, в конец файла:

```ini
[Server]
; Включить работу с домашним сервером
enabled = True

; Идентификатор сервера — подставляется в srv://<id>/…
; ВНИМАНИЕ: менять нельзя, он записан в очередь и плейлисты
server_id = home

; Адрес. Его менять можно свободно — в БД он не хранится
base_url = http://127.0.0.1:8000

; Токен доступа, пока пусто
token =

; Таймаут HTTP-запросов, секунд
timeout = 5

; Буфер сети для VLC, мс
network_caching = 1500
```

**Читать только через `fallback=`**, иначе старый `config.txt` рядом с собранным `.exe`
уронит приложение (`NoSectionError`). Отсутствие секции целиком = `enabled = False`.

В `sources.py`, рядом с уже читаемым `idxDirrs`:

```python
SRV_ENABLED  = config.getboolean('Server', 'enabled',  fallback=False)
SRV_ID       = config.get('Server', 'server_id',       fallback='home')
SRV_BASE_URL = config.get('Server', 'base_url',        fallback='').rstrip('/')
SRV_TOKEN    = config.get('Server', 'token',           fallback='').strip()
SRV_TIMEOUT  = config.getfloat('Server', 'timeout',    fallback=5.0)
SRV_CACHING  = config.getint('Server', 'network_caching', fallback=1500)
```

Зависимость: `requests` в `requirements.txt` (и позже в `hiddenimports` в `player.spec`).

## 3.2 Разбор URI — единственное место

```python
def _parse(self, uri):
    """'srv://home/t/48213' -> ('t', '48213');  'srv://home/d/Rock/Muse' -> ('d', 'Rock/Muse')
    Корень сервера: 'srv://home/d' или 'srv://home/d/' -> ('d', '')"""
```

Реализация — строковые операции, никакого `Path`. Отрезать префикс `srv://`, отделить
`server_id` до первого `/`, затем тип (`t` или `d`) и остаток. Остаток для `d` —
это `rel_path` в терминах сервера, для `t` — `track_id`.

Обратная сборка — два хелпера:

```python
def _track_uri(self, track_id) -> str:   # f"srv://{SRV_ID}/t/{track_id}"
def _dir_uri(self, rel_path) -> str:     # f"srv://{SRV_ID}/d/{rel_path}"  (rel_path без ведущего /)
```

Чужой `server_id` в URI (лежит в плейлисте от другого сервера) — логировать и вести
себя как с недоступным треком, а не падать.

## 3.3 HTTP-обёртка

```python
def _get(self, path, params=None, stream=False):
    """GET к серверу. Возвращает Response или бросает RemoteUnavailable."""
```

Требования:
* `timeout=SRV_TIMEOUT` на **каждом** запросе — без исключений. Выключенный Pi иначе
  вешает UI на минуту (TCP-таймаут по умолчанию).
* Заголовок `Authorization: Bearer <token>`, если токен не пуст.
* Один `requests.Session()` на весь класс — переиспользование TCP-соединения даёт
  заметную разницу при добавлении альбома.
* Любая сетевая ошибка (`ConnectionError`, `Timeout`, 5xx) → своё исключение
  `RemoteUnavailable`. 404/410 → `RemoteNotFound`. Наружу из методов источника
  исключения **не выпускать**: `meta` возвращает заглушку, `cover` — `None`,
  `list_dir` — `[]`. Причина: вызывающий код (`add_queue`, `rebuild_explorer`) писался
  под локальный источник и падение не переживёт.
* Логировать один раз на запрос, не на каждый retry.

Кэш меты в памяти: `dict[track_id] -> (timestamp, data)`, TTL 60 с, размер ≤ 2000
записей. Без него `rebuild_queue_ui` при прокрутке очереди дёрнет сервер на каждую
видимую строку.

## 3.4 Методы

Сигнатуры — один в один как у `LocalSource`.

| Метод | Реализация | Сеть |
|---|---|---|
| `is_dir(uri)` | `_parse(uri)[0] == 'd'` | нет |
| `mrl(uri)` | `f"{BASE}/server/stream/{id}"`, id через `_parse` | нет |
| `parent(uri)` | для `t/<id>` — папка трека (нужен `rel_path` из меты, берётся из кэша); для `d/<rel>` — обрезать последний сегмент, для корня вернуть себя | нет* |
| `display_path(uri)` | `"Сервер"` для корня, иначе `"Сервер/" + rel_path` | нет |
| `exists(uri)` | `True`, если `_parse` разобрал URI | нет |
| `reveal(uri)` | `pass` | нет |
| `list_dir(uri)` | `GET /server/browse?folder_path=<rel>` | 1 запрос |
| `meta(uri)` | `GET /server/track/<id>` → словарь с русскими ключами | 1 запрос |
| `details(uri)` | тот же ответ, что и `meta` (из кэша) → второй словарь | 0–1 |
| `cover(uri, size)` | `GET /server/track/<id>/cover?size=50\|full` → `.content` | 1 запрос |
| `expand(uri)` | `GET /server/tracks_under?folder_path=<rel>` → список URI | 1 запрос |

\* `parent` для трека требует `rel_path`; если меты в кэше нет — вернуть корень
`srv://home/d`, это не критично.

### Формат `meta` — ключи должны совпадать с локальными

```python
{
    "Название": row["name"],
    "Автор":    row["author"] or "Неизвестно",
    "Альбом":   row["album"],
    "Год":      row["year"],
    "Жанр":     row["genre"],
}
```

При недоступности сервера: `{"Название": f"Трек {id} (сервер недоступен)", "Автор": None, ...}` —
`add_queue` и `on_item_click` кладут это в БД, и строка в очереди остаётся читаемой.

### Формат `details` — форматирование на клиенте

Сервер отдаёт числа (`duration: 269.39`, `bitrate: 974`), а UI ждёт строки в том же
виде, что делает `LocalSource.details`:

```python
{
    "Длительность": f"{duration:.2f} сек",
    "Частота":      f"{sample_rate} Гц",
    "Битрейт":      f"{bitrate} kbps",     # сервер УЖЕ отдаёт кбит/с, делить на 1000 НЕ нужно
    "Глубина бит":  bits,                  # ключ добавлять, только если bits не None
    "Каналы":       f"{channels}",
}
```

Расхождение с `LocalSource` здесь — это расхождение в UI, а его увидит глаз.

### Формат `list_dir` — как у локального

```python
[{"name": ..., "path": <URI>, "type": "folder"|"track"}]
```

Сервер отдаёт папки как `{"name", "path": rel_path, "type": "folder"}`, треки —
как строки БД с `id`. Превратить: папки → `_dir_uri(rel_path)`, треки →
`_track_uri(id)`, `name` для трека брать из тега (`row["name"]`), а не из имени файла.
Сортировка уже сделана сервером — не пересортировывать.

Заодно сложить мету треков в кэш: список уже содержит `name`, `author`, `duration` —
это экономит по запросу на трек при добавлении в очередь.

### `expand` — нужен новый эндпоинт

`db.tracks_under_dir()` на сервере уже написан и не используется. Добавить в
`server.py` (~8 строк):

```python
@app.get("/server/tracks_under")
def tracks_under(folder_path: str = ""):
    safe_path(folder_path)                       # проверка обхода каталога
    with closing(db.get_conn(cfg.db_path)) as con:
        return [dict(r) for r in db.tracks_under_dir(con, folder_path)]
```

`RemoteSource.expand` возвращает `[self._track_uri(r["id"]) for r in rows]` и кладёт
меты в кэш.

## 3.5 VLC: сетевой буфер

В `utils.create_player` добавить в `vlc_args`:

```python
f'--network-caching={sources.SRV_CACHING}',
```

На локальные файлы не влияет. Без него старт сетевого трека будет с заиканиями на Wi-Fi.

## 3.6 Проверка Э3

Сервер запущен, `enabled = True`, `base_url` указывает на него.

| Что делаем | Ожидание |
|---|---|
| `python -c "import sources; s=sources.get('srv://home/t/1'); print(s.meta(...), s.details(...))"` | русские ключи, значения из базы сервера |
| `sources.get('srv://home/d').list_dir(...)` | список папок с `srv://home/d/…` в `path` |
| `expand('srv://home/d')` | все треки библиотеки, `srv://home/t/<id>` |

| Вписать `UPDATE queue SET path='srv://home/t/1' WHERE id=0`, нажать Play | играет, название и обложка в интерфейсе правильные |
| Перемотка слайдером по этому треку | попадает в нужную секунду |
| Остановить сервер, нажать Play | UI не виснет дольше `timeout`, в логе ошибка, приложение живо |
| `enabled = False` | ни одного сетевого запроса (проверить по логу uvicorn) |
| Локальные треки | всё как раньше — прогнать блок «Воспроизведение» из регрессии |

# Э4. Проводник по серверу

## 4.0 Задача

Сейчас проводник начинается со `start_path` из конфига и ходит только по диску.
Нужно, чтобы одним переключателем он показывал библиотеку сервера, а всё остальное —
двойной клик, drag&drop, контекстное меню, хлебные крошки — работало **тем же кодом**.

Хорошая новость: `rebuild_explorer`, `on_item_click`, `on_segment_click` уже
источник-независимы после Э1. Менять нужно только то, что решает, **какой URI**
показать.

## 4.1 Переключатель

Два сегмента, «Локально» и «Сервер», над адресной строкой (в `gui2.py` рядом с
`address_bar`, ~строка 1144). `ft.SegmentedButton` или две `ft.TextButton` —
на твой вкус, стиль брать из `ui_config.txt`, как у остальных элементов.

Поведение:
* «Локально» → `rebuild_explorer(sources.LOCAL.list_dir(last_local), last_local)`
* «Сервер» → то же с `srv://<server_id>/d`
* Плеер запоминает последнюю папку каждого режима в переменных модуля, чтобы
  переключение туда-обратно не сбрасывало в корень.
* Если `enabled = False` или `ping` не ответил — сегмент «Сервер» серый и некликабельный.
  Тултип: «Сервер не отвечает».

## 4.2 Проверка доступности

Функция `sources.REMOTE.ping()` → `dict | None`:
* `GET /server/ping` с коротким таймаутом (2 с, не `SRV_TIMEOUT`).
* Вызывается **в фоновом потоке после отрисовки UI**, никогда в пути запуска
  (`main.py` синхронный — см. `TZ_streaming.md`, 2.4).
* Результат кладётся в переменную модуля; UI обновляется через
  `page.pubsub.send_all_on_topic("server_status", ...)`, как уже делается для тегов.
* Повтор раз в 30 с, пока сервер недоступен, — чтобы Pi, включённый после плеера,
  подхватился сам.

Сверка `library_uuid`: при первом успешном ping сохранить его; если позже сервер
ответил другим uuid — показать предупреждение «библиотека на сервере пересоздана,
серверные треки в плейлистах могут указывать на другие песни». Молча играть чужое
хуже, чем сказать.

## 4.3 Хлебные крошки

`build_breadcrumbs` (`gui2.py:676`) сейчас режет строку по `/` и склеивает обратно
через `sources.get(sub_path).display_path(sub_path)`. Для сервера `display_path`
отдаёт `Сервер/Rock/Muse` — сегменты получатся правильные, но собранный обратно
`sub_path` будет `Сервер/Rock`, а не URI.

Решение: `build_breadcrumbs` должна получать **URI**, а не отображаемую строку, и
собирать промежуточные пути через источник:

```python
def build_breadcrumbs(uri):
    src = sources.get(uri)
    segments = src.crumbs(uri)      # [(подпись, URI), ...]
```

Новый метод `crumbs(uri)` у обоих источников:
* `LocalSource`: `C:\music\Rock\Muse` → `[("C:", "C:\\"), ("music", "C:\\music"), ...]`
  — ровно та логика, что сейчас внутри `build_breadcrumbs`, перенесённая в источник.
* `RemoteSource`: `srv://home/d/Rock/Muse` → `[("Сервер", "srv://home/d"),
  ("Rock", "srv://home/d/Rock"), ("Muse", "srv://home/d/Rock/Muse")]`.

`build_breadcrumbs` после этого — чистая отрисовка `ft.TextSpan`, без разбора путей.
Это последнее место в `gui2.py`, которое знает про устройство путей.

## 4.4 Кнопка выбора папки

`handle_pick_folder` (`gui2.py:1130`) открывает системный диалог tkinter — для
сервера бессмысленно. В режиме «Сервер» кнопку скрыть или сделать неактивной.

## 4.5 Поиск

`perform_search` (`gui2.py:1154`) фильтрует `explorer_tree.all_items` в памяти, то
есть только текущую папку. Для сервера:

* запрос уходит в `GET /server/search?filename=<q>` (переименовать параметр в `q`
  при желании — контракт твой);
* **в фоновом потоке**, с задержкой 300 мс после последнего нажатия клавиши
  (debounce), иначе каждый символ — это запрос;
* результат рисуется тем же `rebuild_explorer(items, current_dir, is_search=True)`;
* при пустом запросе — возврат к содержимому папки.

Для локального режима поведение не меняется.

Формально это Э6, но здесь оно почти бесплатно — эндпоинт готов, `list_dir` уже
конвертирует строки в URI. Если решишь делать, ограничься серверной веткой.

## 4.6 Метка недоступности

По `TZ_streaming.md` 2.3: серверные треки в очереди и плейлистах при недоступном
сервере не удаляются, а показываются серыми. Точки: `build_queue_cell`
(`gui2.py:976`) и `build_playlist_cell` (`gui2.py:1407`) — если
`sources.is_remote(path)` и сервер не отвечает, красить текст в `--muted` и добавлять
иконку. Данные для отрисовки (`name`, `cov_bytes`) уже лежат в БД, сеть не нужна.

## 4.7 Проверка Э4

| Что делаем | Ожидание |
|---|---|
| Переключить на «Сервер» | корень библиотеки, папки видны |
| Двойной клик по папке | заходит внутрь, крошки обновились |
| Клик по сегменту крошек | возврат на нужный уровень |
| Кнопка «…» вверх | на уровень выше, из корня не уходит «за» сервер |
| Двойной клик по треку | играет, обложка и теги на месте |
| Контекстное меню → «Добавить в очередь» | трек добавился, `path` = `srv://…` |
| Контекстное меню → «Расположение файла» | ничего не происходит, ошибки нет |
| Drag&drop трека с сервера в очередь | работает |
| Переключить на «Локально» и обратно | обе папки запомнились |
| Выключить сервер, переключиться на «Сервер» | сегмент неактивен, приложение живо |
| Включить сервер обратно, подождать 30 с | сегмент снова активен без перезапуска |
| Весь блок «Проводник» из регрессии, локальный режим | без изменений |
