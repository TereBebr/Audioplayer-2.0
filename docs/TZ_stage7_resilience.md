# ТЗ: Э7 «Устойчивость» — по факту

Дополнение к `TZ_streaming.md`. Цель этапа: серверный трек при плохой сети или выключенном
Pi не ломает плеер, а `.exe` собирается и запускается.

UI-решения приняты владельцем проекта (все варианты «а»): индикатор вместо кнопки Play,
всплывающая полоска внизу окна, пропущенные треки серым, пауза с сообщением после серии неудач.

---

## 7.1 Слайдер — ✅

`player.get_length()` для сетевого потока первые секунды отдаёт `-1`, слайдер был мёртвым.

* `sources.*.duration(uri)` — длительность в секундах или `None`. У `RemoteSource` — из
  индекса сервера (строка уже в кэше после `meta`), у `LocalSource` — всегда `None`:
  локальный файл VLC знает сразу.
* `load_track` кладёт её в `ui_utils.known_duration`; `bg_ui_process` берёт
  `get_length()`, а пока он `<= 0` — `known_duration`.

## 7.2 Фоновый цикл воспроизведения — ✅

`ui_utils.bg_ui_process` переписан. Всё тело цикла под `try`: исключение пишется в лог
через `logger.exception`, поток не умирает (грабли из HANDOFF, раздел 6). Очередь двигает
отдельная `_advance_queue()` — только БД.

| Что видит цикл | Что делает |
|---|---|
| `Playing`, время идёт | позиция в слайдер, индикатор скрыт; после 2 с игры трек считается «пошедшим»: счётчик неудач сброшен, трек убран из `failed_uris` |
| `Playing`, время стоит > 1 с | индикатор загрузки (буферизация) |
| `Playing`, время стоит > `stall_timeout` (10 с) | **обрыв**: `stop()` и как при ошибке. Нужно потому, что при пропавшем сервере VLC **не** уходит в `Error`/`Ended`, а висит в `Playing` с замершим временем |
| `Opening`/`Buffering` > 0,5 с | индикатор загрузки |
| `Error` | неудача (см. ниже) |
| `Ended`, а трек так и не заиграл (`last_pos == 0`) | неудача: VLC иногда отдаёт `Ended` вместо `Error` |
| `Ended` серверного трека раньше конца больше чем на 3 с | обрыв → неудача |
| `Ended` нормально | следующий трек |

**Неудача** (`track_failed`):

1. Серверный трек и опрос считает сервер доступным → повтор через `retry_delays`
   (1, 2, 4 с), полоска «Связь потеряна, повтор N/3». Повтор — `set_mrl` + `play`, после
   старта `set_time` на последнюю позицию: трек продолжается с места обрыва.
2. Повторы кончились, трек локальный или сервер уже известен как недоступный → трек в
   `ui_utils.failed_uris` (серым в очереди и плейлисте), полоска «Трек недоступен,
   пропущен», следующий трек.
3. `max_fail_streak` (3) треков подряд не открылись → `stop()`, кнопка «Play», полоска
   «Сервер недоступен, воспроизведение остановлено». Дальше не листаем.

`failed_uris` очищается, когда опрос видит, что сервер вернулся.

**UI** — только через pubsub (`gui2.py`):
* `player_state {"buffering": bool}` — `play_spinner` вместо `play_btn`: логотип
  `assets/icons/loading_ico.png`, крутится через `animate_rotation` — `spin_logo()` раз в
  секунду добавляет оборот, пока индикатор виден;
* `player_state {"stopped": True}` — кнопка «Play», перерисовка очереди;
* `player_notice {"text"}` — `ft.SnackBar` на 3 с.

## 7.3 Старт и выключенный сервер — ✅

* `RemoteSource._get` — единственная точка выхода в сеть:
  * `enabled = False` → сразу `RemoteUnavailable`, запросов ноль;
  * опрос считает сервер недоступным → сразу `RemoteUnavailable`, без ожидания таймаута.
    Сам опрос (`ping`) идёт с `probe=True`, иначе не узнал бы, что сервер вернулся.
    Именно это убрало ~10 с ожидания на каждом пропускаемом треке.
* `load_track` при `enabled = False` серверный трек не загружает (VLC пошёл бы по http
  сам, мимо `_get`), полоска «Сервер выключен в настройках».
* `start_path` с `srv://` заменяется на `./music` с предупреждением в логе: список
  стартовой папки читается при импорте `gui2`, до появления окна.

`player.spec`: в `hiddenimports` добавлены `sources`, `cover_worker`, `queue_worker`,

## Доработки после проверки владельцем — ✅

* **Сервер выключили, пока проводник в режиме «Сервер».** Опрос при доступном сервере идёт
  раз в 60 с, и всё это время переключатель пускал в «Сервер»: клик ждал таймаут, индикатор
  загрузки висел поверх списка. Теперь:
  * `RemoteSource._get` при сетевой ошибке ставит `sources._wake` — опрос просыпается и
    проверяет сервер сразу (`_wake.wait(...)` вместо `time.sleep`). Через 1–2 с сегмент
    «Сервер» блокируется, проводник уходит в локальный режим;
  * `open_dir` для локальной папки сбрасывает `_pending_dir`, таймер и индикатор:
    раньше висящая загрузка серверной папки оставляла индикатор над локальным списком, а
    её запоздавший ответ мог перерисовать проводник пустой серверной папкой.

## Настройки — `config.txt`, `[Server]`

| Ключ | По умолчанию | Что |
|---|---|---|
| `retry_delays` | `1, 2, 4` | паузы между повторами, секунд; сколько чисел — столько повторов |
| `max_fail_streak` | `3` | после скольких неудачных треков подряд встать на паузу |
| `stall_timeout` | `10` | сколько секунд трек может стоять, прежде чем это обрыв |
| `network_caching` | `5000` | буфер VLC, мс (уже был) |

## Проверено вживую (локальный uvicorn)

* серверный трек: длительность видна с 0:00;
* сервер убит, перемотка вперёд → индикатор, «повтор 1/3»; сервер поднят → трек сам
  продолжился с той же секунды (03:13 → 03:17 → 03:22);
* плеер запущен при выключенном сервере, Play на серверном треке → три быстрых пропуска
  с полоской, после третьего — стоп, кнопка «Play»;
* `enabled = False` (подменой в процессе): `search`, `meta`, `ping` — ноль HTTP-запросов.
