# ТЗ: воспроизведение музыки с домашнего сервера (Raspberry Pi 4 + HDD)

Статус: черновик к реализации.
Цель: плеер должен уметь брать треки не только с локального диска, но и с домашнего
сервера по сети, при этом вся существующая логика (очередь, плейлисты, drag&drop,
горячие клавиши, автопереход) должна работать без дублирования кода.

---

## 0. Ключевое архитектурное решение (прочитать первым)

Изначальная идея — «сделаем `load_track` с другими аргументами, отдельную функцию для
стриминга» — работать будет, но её лучше не делать. Причина:

`load_track` вызывается из 6 мест (`gui2.py:803, 829, 862, 914, 951, 1365`) плюс из
`play_next_or_pred` (`ui_utils.py:455`) и из авто-перехода в фоне (`ui_utils.py:885`).
Если появится второй `load_track_remote`, то каждое из этих мест придётся научить
выбирать между двумя функциями, и то же самое произойдёт с `add_queue`,
`add_track_to_playlist`, `get_folder_content`, `extract_cover_miniature`. Получится
два параллельных кодовых пути, и каждая новая фича будет писаться дважды.

**Вместо этого: один `load_track`, но за ним — слой источников (source layer).**

Идея в том, что весь код выше уровня источника работает с треком как с непрозрачной
строкой-адресом (URI) и никогда сам не лезет в файловую систему. Всё, что реально
трогает диск или сеть, живёт в двух классах с одинаковым интерфейсом:

```
                 load_track / add_queue / explorer / плейлисты
                                  |
                          sources.get(uri)  ->  Source
                                  |
                 +----------------+----------------+
                 |                                 |
           LocalSource                       RemoteSource
      (mutagen + Path + диск)          (HTTP к Raspberry Pi)
```

Что это даёт:
* сигнатура `load_track(page, uri, play_btn_obj, idx)` **не меняется**;
* `queue.db` / `app.db` не меняют схему — в колонке `path` просто лежит URI;
* drag&drop, поиск, перемешивание, история — не трогаем вообще;
* VLC и так умеет играть `http://...` через `media_new()`, отдельный движок не нужен.

## 1. Схема адресации треков (URI)

Единый формат строки, который лежит в `queue.path` и `tracks.path`.

| Источник | Формат | Пример |
|---|---|---|
| Локальный файл | абсолютный путь как сейчас | `C:\music\used\144.Raven.flac` |
| Сервер, трек | `srv://<server_id>/t/<track_id>` | `srv://home/t/48213` |
| Сервер, папка | `srv://<server_id>/d/<путь>` | `srv://home/d/Rock/Muse` |

**Почему не хранить прямо `http://192.168.1.50:8080/...`:**
IP или порт Pi однажды поменяются, и все плейлисты умрут. `server_id` — это ключ из
`config.txt`, который резолвится в base_url на лету.

**Почему `track_id`, а не путь к файлу на HDD:**
переименование или перенос файла на сервере не должно рвать плейлисты. `track_id` —
стабильный идентификатор из индекса сервера.

Детектор источника — одна функция, и только она решает, локальный это трек или нет:

```python
def is_remote(uri: str) -> bool:
    return isinstance(uri, str) and uri.startswith("srv://")
```

> ⚠️ Правило, которое надо соблюдать жёстко: **нигде выше слоя источников нельзя
> вызывать `Path(uri)`**. На Windows `Path("srv://home/t/48213").resolve()` молча
> превратится в `C:\Users\...\srv:\home\t\48213`. Это будет самый частый баг при
> реализации.

## 2. Режимы работы и обратная совместимость

Это не «локальная версия» и «серверная версия». Это **один плеер, у которого два
источника доступны одновременно**, и сервер — необязательная надстройка. Требование
формулируется так:

> Плеер без сервера, с сервером и с выключенным сервером должен вести себя
> одинаково хорошо. Ни одна из существующих функций не деградирует.

### 2.1 Три состояния, все рабочие

| Состояние | Что должно быть | Чего быть не должно |
|---|---|---|
| `enabled = False` | всё как сейчас, до последней кнопки | ни одного сетевого вызова вообще, даже ping |
| `enabled = True`, сервер отвечает | локальный и серверный источники в одном интерфейсе | локальное воспроизведение не становится медленнее |
| `enabled = True`, сервер недоступен | локальная часть работает полностью | зависаний UI, падений, чистки очереди и плейлистов |

### 2.2 Смешанные очередь и плейлисты
Очередь может содержать локальные и серверные треки вперемешку — это нормальный
сценарий, а не крайний случай. Автопереход `локальный → серверный → локальный` обязан
работать. То же для плейлистов: в одном плейлисте лежат и те, и другие.

### 2.3 Что делать с серверными треками, когда сервера нет
* **Не удалять** их из очереди и плейлистов — очередь пользователя не наша, чтобы её
  чистить.
* Показывать их с пометкой недоступности (серый текст, иконка) — миниатюра и название
  уже лежат в `queue.cov_bytes` / `queue.name`, так что список рисуется без сети.
* Попытка воспроизведения: сообщение и переход к следующему треку, а не тишина и не
  зависший плеер.

### 2.4 Старт приложения не ждёт сеть
`/api/ping` вызывается **в фоновом потоке после отрисовки UI**, с коротким таймаутом.
Сейчас `main.py` целиком синхронный: если положить проверку сервера в путь запуска, при
выключенном Pi окно плеера не появится несколько секунд, а при севшем роутере — до
таймаута TCP.

### 2.5 Существующие базы читаются как есть
В `app.db` и `queue.db` уже лежат реальные данные с локальными путями. После
рефакторинга они должны открыться без миграции: локальный путь — это валидный URI по
схеме из раздела 1, и `is_remote()` для него вернёт `False`. Никаких скриптов
конвертации, никакого «удалите базу и начните заново».

### 2.6 Старый `config.txt` не должен ронять приложение
Сейчас конфиг читается почти везде без `fallback` — единственное исключение
`start_path` в `gui2.py:27`. Если добавить `config.getboolean('Server', 'enabled')` без
fallback, то любой, кто обновит `.exe`, но оставит свой старый `config.txt`, получит
`NoSectionError` на старте. **Все чтения секции `[Server]` — только с `fallback=`**, и
отсутствие секции целиком означает `enabled = False`.

### 2.7 Сборка
`player.spec` перечисляет модули явно в `hiddenimports`. Туда нужно добавить
`sources` и HTTP-клиент (`requests` или `httpx`) — PyInstaller не найдёт их сам через
`collect_all("flet")`. Проверяется запуском собранного `dist/Player/Player.exe`, а не
только `python main.py`.

### 2.8 Один и тот же файл с двух сторон
Если трек лежит и на диске, и на сервере — это два разных URI и, следовательно, два
разных трека в таблице `tracks`. Дедупликацию по тегам не делаем: она даст ложные
срабатывания на разных изданиях одного альбома. Поведение фиксируем как ожидаемое.

## 3. Серверная часть (Raspberry Pi 4)

### 3.1 Железо и ОС
* Raspberry Pi OS Lite (64-bit), без десктопа.
* HDD в USB 3.0 порт (синий), файловая система ext4 (NTFS через ntfs-3g даёт
  заметный оверхед на CPU при обходе больших папок).
* Монтирование по UUID через `/etc/fstab`, а не по `/dev/sda1` — иначе после
  перезагрузки с воткнутой флешкой диск уедет на другую букву:
  `UUID=... /mnt/music ext4 defaults,nofail,noatime 0 2`
* Питание HDD: 2.5" диск от USB Pi может недобирать ток — нужен либо блок питания
  на 3A+, либо HDD с внешним питанием. Симптом нехватки — диск отваливается
  посреди воспроизведения.
* Статический IP или DHCP-резервация на роутере, плюс mDNS-имя (`music.local`).

### 3.2 Стек
* Python 3.11+, FastAPI + uvicorn (тот же язык, что и плеер — можно переиспользовать
  `utils.get_audio_tags` / `utils.tec_info` / `utils.get_audio_info` почти как есть).
* SQLite `library.db` на самом Pi — индекс библиотеки.
* Обложки — не в БД, а в кэш-папку на диске: `/mnt/music/.cache/covers/<track_id>_50.jpg`
  и `<track_id>_full.jpg`.

### 3.3 Индексатор
Подробное ТЗ — в `TZ_indexer.md`. Здесь кратко.

Отдельный скрипт/фоновая задача, которая обходит `/mnt/music`, для каждого файла с
поддерживаемым расширением (`.mp3 .flac .wav .ogg .m4a .mp4`) читает теги mutagen и
пишет строку в `library.db`.

Схема `tracks` на сервере:

| поле | тип | смысл |
|---|---|---|
| id | INTEGER PK | тот самый `track_id` в URI |
| rel_path | TEXT UNIQUE | путь относительно корня библиотеки |
| name, author, album, year, genre | TEXT | теги |
| duration | REAL | секунды |
| sample_rate, bitrate, channels, bits | INTEGER | тех. данные |
| size, mtime | INTEGER | для инкрементального пересканирования |
| has_cover | INTEGER | 0/1 |

Пересканирование: сравнивать `size + mtime`, не перечитывать неизменившиеся файлы.
Полный проход по HDD с несколькими десятками тысяч треков — минуты, поэтому он
должен быть фоновым и запускаться по таймеру + по эндпоинту `POST /api/rescan`.

### 3.4 API

| Метод | Путь | Ответ | Назначение |
|---|---|---|---|
| GET | `/api/ping` | `{"ok":true,"version":"1.0","library_count":12043}` | проверка доступности при старте плеера |
| GET | `/api/browse?path=<rel>` | `[{"name","uri","type":"folder"\|"track","author","duration"}]` | содержимое папки — прямой аналог `get_folder_content` |
| GET | `/api/search?q=<str>&limit=200` | тот же формат | поиск по всей библиотеке (сейчас `perform_search` ищет только в текущей папке) |
| GET | `/api/track/<id>` | полный JSON тегов + тех. данных | замена `mutagen.File()` + `get_audio_info` |
| GET | `/api/track/<id>/cover?size=50\|full` | image/jpeg | замена `extract_cover_miniature` / `extract_cover` |
| GET | `/api/tracks?ids=1,2,3` | массив мета | батч-запрос при добавлении папки в очередь |
| GET | `/api/stream/<id>` | audio/*, **обязательно с поддержкой HTTP Range** | сам звук |
| POST | `/api/rescan` | `{"started":true}` | принудительная переиндексация |

**Про Range — критично.** Без ответа `206 Partial Content` перемотка
(`player.set_time()` в `ui_utils.py:356`) работать не будет: VLC умеет seek по HTTP
только если сервер отдаёт диапазоны. В FastAPI `FileResponse` это делает из коробки,
но если писать отдачу вручную через `StreamingResponse` — Range надо реализовать
самому. Проверять curl'ом:
`curl -r 0-1023 -o /dev/null -D - http://music.local:8080/api/stream/1` → должно быть
`HTTP/1.1 206` и заголовок `Content-Range`.

**Транскодинг не нужен.** FLAC — это ~1.0–1.5 Мбит/с, гигабитная (и даже Wi-Fi)
домашняя сеть это тянет с запасом, а Pi 4 при перекодировании будет греться зря.
Отдаём файл как есть.

### 3.5 Авторизация
Сеть домашняя, но открывать библиотеку в LAN без всякой защиты не стоит.
Минимальный вариант: статический токен, который плеер шлёт в заголовке
`Authorization: Bearer <token>` для всех JSON-эндпоинтов.

Отдельная проблема — `/api/stream/<id>`: заголовок туда пойдёт от VLC, а не от
Python, и произвольные заголовки через python-vlc задать неудобно. Варианты:
1. токен в query (`?t=...`) только для стрима — просто, но токен попадает в логи
   сервера и в историю процессов; для домашней сети приемлемо, но лучше выдавать
   отдельный короткоживущий stream-токен через `/api/session`, а не тот же самый,
   что и основной;
2. HTTP Basic — VLC умеет `http://user:pass@host/...` в MRL, но пароль так же
   оказывается в строке;
3. вообще без авторизации на стриме, если сервер слушает только LAN-интерфейс и
   закрыт файрволом (`ufw allow from 192.168.1.0/24`).

Рекомендация: вариант 1 (короткоживущий stream-токен) + ufw по подсети.
Наружу в интернет порт не пробрасывать — если это понадобится, это отдельная задача
с HTTPS и нормальной аутентификацией, в этом ТЗ она не решается.

### 3.6 Автозапуск
systemd-юнит `/etc/systemd/system/musicserver.service` с `Restart=always`,
`After=network-online.target` и `RequiresMountsFor=/mnt/music` (иначе сервер
стартует раньше, чем примонтируется HDD, и проиндексирует пустоту).

## 4. Клиентская часть (плеер)

### 4.1 Новый модуль `sources.py`

```python
# sources.py
class Source:
    """Интерфейс источника треков. Всё, что трогает диск или сеть, — только здесь."""

    def list_dir(self, uri) -> list[dict]:
        """[{'name','path','type'}] — ровно то, что сейчас возвращает get_folder_content."""

    def expand(self, uri) -> list[str]:
        """URI папки -> плоский список URI треков (аналог rglob в add_queue)."""

    def mrl(self, uri) -> str:
        """Что скормить VLC: локальный путь или http-URL стрима."""

    def meta(self, uri) -> dict:
        """{'Название','Автор','Альбом','Год','Жанр'} — как get_audio_tags."""

    def details(self, uri) -> dict:
        """{'Длительность','Частота','Битрейт',...} — как get_audio_info."""

    def cover(self, uri, size='full') -> bytes | None:
        """Обложка. size='mini' -> 50x50 для очереди."""

    def exists(self, uri) -> bool: ...
    def parent(self, uri) -> str: ...
    def display_path(self, uri) -> str:
        """Человекочитаемая строка для адресной строки/хлебных крошек."""


def get(uri) -> Source:
    """Единственная точка выбора источника."""
    return REMOTE if is_remote(uri) else LOCAL
```

`LocalSource` пишется первым и представляет собой **перенос уже существующего кода**
без изменения поведения: `get_folder_content` → `list_dir`, `get_audio_tags` →
`meta`, `extract_cover_miniature` → `cover(size='mini')` и т.д. После этого шага
приложение должно работать ровно как раньше — это отдельный коммит и отдельная
проверка.

`RemoteSource` — HTTP-клиент к API из раздела 3.4 (`requests` или `httpx`), с
таймаутами, ретраями и кэшем.

### 4.3 Конфиг

Новая секция в `config.txt`:

```ini
[Server]
; Включить работу с домашним сервером
enabled = True

; Идентификатор сервера — то, что подставляется в srv://<id>/...
; Менять нельзя: он записан в очередь и плейлисты
server_id = home

; Адрес сервера. Его можно менять свободно — в БД он не хранится
base_url = http://music.local:8080

; Токен доступа
token =

; Сколько ждать ответа API, секунд
timeout = 5

; Буфер сети для VLC, мс. Больше = устойчивее к лагам Wi-Fi, но дольше старт трека
network_caching = 1500

; Кэш обложек на диске, МБ. 0 = не ограничивать
cover_cache_mb = 200
```

### 4.4 Кэш на стороне плеера
* Обложки-миниатюры уже кэшируются самим фактом хранения в `queue.cov_bytes` /
  `tracks.cov_bytes` — их берём из `/api/track/<id>/cover?size=50` один раз при
  добавлении в очередь.
* Большие обложки и мету — LRU-кэш в памяти на сессию + папка `storage/cache/`.
* Сетевые запросы **никогда** не выполнять в UI-потоке flet: подвиснет весь
  интерфейс. Мета для отображения тянется в отдельном потоке, UI обновляется через
  уже используемый `page.pubsub.send_all_on_topic(...)`.

### 4.5 Поведение при проблемах сети
Сейчас `bg_ui_process` (`ui_utils.py:820`) знает только два состояния: «играет» и
`Ended`. Для сети этого мало:

| Состояние VLC | Что делать |
|---|---|
| `Buffering` | показать индикатор, **не** считать это концом трека, не переключать |
| `Error` | залогировать, показать уведомление, через 1–2 с попробовать ещё раз, потом перейти к следующему треку |
| `Ended` при `get_time() < duration - 2s` | это обрыв, а не конец: повторить с текущей позиции, а не переключать трек |
| сервер недоступен при старте приложения | `enabled=True`, но `/api/ping` не отвечает → работать в локальном режиме, remote-ветку проводника показать серым |

Отдельно: `player.get_length()` для сетевого потока возвращает `-1` в первые
секунды. Сейчас в `bg_ui_process` из этого выйдет `total_sec = 0` и сломанный
слайдер. Решение: длительность брать из меты сервера (`duration`), а `get_length()`
использовать только как уточнение, когда он станет `> 0`.

## 6. Подводные камни (список для самопроверки)

1. **`Path()` на URI.** Самая частая будущая ошибка. По возможности — assert в
   `LocalSource`, что на вход не пришла строка с `srv://`.
2. **`add_queue` для папки с сервера.** Если делать «в лоб», добавление альбома на
   50 треков = 50 HTTP-запросов меты + 50 запросов обложек, интерфейс встанет.
   Нужен батч-эндпоинт и добавление в очередь одной транзакцией.
3. **Обложки в `cov_bytes`.** Сейчас в `queue.db` уже 2.9 МБ при небольшой очереди —
   это BLOB'ы миниатюр. С библиотекой на HDD база распухнет. Есть смысл заодно
   перейти на хранение пути к файлу обложки вместо байтов (в коде уже висит
   `TODO: перевести на файловую систему` в `ui_utils.py`).
4. **Уникальность в `tracks.path`.** Код ищет трек через
   `SELECT id FROM tracks WHERE path = ?` — URI обязаны быть канонические, без
   вариантов написания (без завершающего слэша, в едином регистре хоста).
5. **Смена IP сервера** не должна ломать плейлисты — ради этого `srv://home/...`,
   а не прямой URL.
6. **Одновременный доступ к `queue.db`.** Сетевые операции добавят задержек;
   `PRAGMA journal_mode=WAL` уже включается в `bg_ui_process`, но лучше включать
   его один раз при инициализации в `database.create_queue()`.
7. **Кириллица и пробелы в путях** → URL-кодирование в `mrl()`
   (`urllib.parse.quote`). VLC на неэкранированном URL просто молча не заиграет.
8. **Расширения vs реальный формат.** На сервере тоже пригодится
   `utils.detect_and_load_audio` — файлы с несоответствующим расширением есть, код
   для них уже написан.
9. **Часы Pi.** Без RTC после перезагрузки без сети время уезжает — если когда-нибудь
   появятся короткоживущие токены, они будут отвергаться.
10. **`NoSectionError` на старом `config.txt`.** Все чтения `[Server]` — с `fallback=`
    (см. 2.6). Один пропущенный fallback валит приложение у всех, кто не заменил конфиг.
11. **Сетевой вызов в пути запуска.** Проверка сервера — в фоне, после отрисовки UI
    (см. 2.4). Иначе при выключенном Pi окно не появляется до таймаута.
12. **Обход `sources` где-нибудь в одном месте.** Достаточно одного забытого
    `mutagen.File(path)` в UI-коде, чтобы серверный трек уронил ветку. После Э1 полезно
    прогрепать проект на `mutagen.File`, `Path(`, `os.path`, `open(` вне `sources.py`.
13. **PyInstaller.** `sources` и HTTP-клиент — в `hiddenimports` в `player.spec`
    (см. 2.7). `python main.py` работает, а `.exe` падает на импорте.

## 7. Критерии приёмки

### 7.1 Сетевая часть
1. Трек с сервера запускается двойным кликом из проводника плеера.
2. Перемотка слайдером по сетевому треку попадает в нужную секунду.
3. Автопереход работает в смешанной очереди «локальный → сетевой → локальный».
4. Альбом на 50 треков с сервера добавляется в очередь за < 3 с и не морозит интерфейс.
5. После перезагрузки Raspberry Pi сервер поднимается сам и отдаёт `/api/ping`.

### 7.2 Три состояния плеера
6. `enabled = False`: приложение работает как до всех изменений; в логах нет ни одного
   сетевого обращения.
7. `enabled = True`, Pi выключен: окно открывается без задержки, локальная музыка
   играет, серверные треки в очереди помечены недоступными и не удалены.
8. Pi выдёргивают из сети во время воспроизведения серверного трека: плеер не падает,
   сообщает об ошибке и продолжает работать с локальными файлами.
9. Старый `config.txt` без секции `[Server]`: приложение стартует, сервер выключен.
10. Существующие `app.db` и `queue.db` открываются без миграции, все плейлисты на месте.
11. `dist/Player/Player.exe` собирается и запускается.
